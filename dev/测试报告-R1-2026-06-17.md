- 临时权限:调额 grant、account_ttl 到期反向、撤销回退基线,均 OK。

### 3. 红线(测试)—— 通过
- 明文 API key **仅创建/轮换时回显一次**;列表与详情只见脱敏串(实测 `GyfH3LTY••••X03p`)。
- 客户侧对价格/折扣**只读**(配置仅运营方,管理员 PUT pricing → 403)。

### 4. 计费正确性(商务 / 研发)—— 通过(重点核验)
- **币种 / 换算**:管理员概览「当前余额 **$100**」对应入账 50,000,000 quota(÷500000=$100)。币种显示 **$**,与主站 `QuotaDisplayType=USD` 一致(符合 A3)。
- **折扣换算(A1/A2/G 真机验证)**:配总折扣 0.8 后——
  - 平台镜像:`{pct:0.8, base:1, abs:0.8}`,`user_group:"org_8"`,`upstream_special_ratio.default:0.8`(平台读 new-api 回显)。
  - new-api 侧实证:用户 `o8m12` 的 `group=org_8`(身份+折扣),令牌 `group=default`(走渠道路由),`GroupGroupRatio` 含 `org_8→default→0.8`。
  - **取消折扣(mode=none)**:`org_8→default` 回退 `1`(基础倍率),正确恢复。
- **退款冲正**:运营方 `POST /debits` 减余额成功 + 强制 reason + 留痕;缺 reason → 400;管理员调用 → 403。

### 5. 零侵入(研发 / 运维)—— 通过(强证据)
- 平台只经官方 API 落数据:new-api 真建了用户(非 mock)。
- **字段所有权/合并保留验证(对应 G 设计)**:`GroupGroupRatio` 写入 `org_*` 各条的同时,**完整保留了 new-api 既有的 `vip→edit_this→0.9`**——平台没有抹掉他人/手工配置。这正是设计要的"只动自己管的 key、merge-preserve 其余"。
- 容器健康:平台/new-api/MySQL 全 Up,服务日志无 ERROR/panic。
