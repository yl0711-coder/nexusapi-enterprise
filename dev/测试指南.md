# NexusAPI 企业管理平台 · 测试指南(交付测试)

> **重要前提**:这是**本机 / 容器测试环境**。平台与一套**一次性的 new-api(rc.4)+ MySQL** 在
> 本机 Docker 里跑,数据全是 **MOCK**(渠道 key 都是假串 `sk-mock-*`)。
> **任何请求都不会打到线上主站**。请勿在此环境填真实密钥 / 真实客户数据。

---

## 1. 访问地址与账号

| 项 | 值 |
|---|---|
| 平台地址 | **http://localhost:18080** |
| 运营方账号 | `ops@nexus.local` / `OpsPass123` |
| new-api 后台(看上游侧) | http://localhost:13000 ,root / `RootPass123` |

> **组织管理员 / 成员的密码怎么来**:不是预置的——
> - 运营方「新建客户组织」后,**响应里一次性回显该组织管理员的初始密码**(请当场记下)。
> - 组织管理员「开通成员」后,**响应里一次性回显该成员的登录邮箱 + 初始密码**。
> 用这些去登录体验「组织管理员 / 成员」视角。

> **若测试不在这台机器上**:要么在本机用内网 IP / 隧道把 18080 暴露给测试;要么测试各自按
> 第 5 节在自己机器起一套(同样全本机、不碰线上)。

## 2. 登录后能测什么(按角色)

**运营方(ops@nexus.local)**
- 客户组织:列表、**新建组织**(连带建管理员账号、回显初始密码)、进入组织看余额/成员
- **充值入账**(给组织加余额数字)、**计费灰度开关**(扣费/硬停,默认关)
- **折扣**:整体折扣 / 按分组折扣(写 new-api 分组特殊倍率)
- **支持会话**:只读支持 / 协助态(进入后以组织管理员身份操作,受后端闸约束)
- **退款冲正**(减余额,需填原因)

**组织管理员(建组织时拿到的账号)**
- 概览(余额 + 近 7 天用量)、团队、层级(可设模型集 / 月度额度 / 单模型日上限)
- **开通成员**(代发 API key,明文 key 仅回显一次)、**批量导入**、调额、停用/恢复
- **审批**(批准/驳回;三档:小额自动通过 / 一审 / 二审)、角色任命、组织设置
- 余额与计费、申请充值、计价(只读回显)

**团队负责人 / 成员**(任命角色 / 开通成员后用其账号登录)
- 团队负责人:本团队成员、审批
- 成员:我的用量、我的 API Key(轮换、IP 白名单)、申请增额、通知

> 主流程一条龙建议:运营方建组织 → 用回显的管理员密码登录 → 建层级 → 开通成员(拿到 API key + 成员密码)
> → 用成员密码登录看自助页 → 回管理员审批成员的申请。

## 3. 涉钱功能怎么测(重要)

- **充值入账 / 余额 / 申请充值 / 退款冲正**:可直接测(运营方入账、管理员申请、运营方冲正)。
- **扣费(读 new-api 日志扣余额)默认关**:要测得运营方先对该组织开「计费灰度」的扣费开关。
  但本环境**没有真实 LLM 调用**(渠道是假的),new-api 不会产生消费日志,所以**界面上看不到自动扣费**——
  这是预期。真实扣费 / 去重 / 守恒 / 硬停链路由**自动化集成测试**覆盖(对真 rc.4 造日志验过,全绿)。
- **硬停(余额到 0 切断成员)默认关**,逐组织开关,误算不会误切付费客户。

## 4. 数据重置 / 环境控制(给会用命令行的)

```bash
# 在仓库根目录
bash dev/reset.sh                                          # 从基准库还原 new-api(清掉造的脏数据)
docker compose -f dev/docker-compose.dev.yml stop          # 不测时停掉(数据保留)
docker compose -f dev/docker-compose.dev.yml start         # 再起
bash dev/run-server.sh                                     # 重启平台 server(见下"排障")
```

**排障**:若**调额 / 折扣 / 开通成员**等返回 `50301 上游鉴权失效`,是有人对 new-api root 取过 token
把平台的管理员凭证旋转了 → 重跑 `bash dev/run-server.sh` 取新凭证即可(生产不会发生)。

## 6. 已知"本期不做 / 降级"(请勿当 Bug 报)

- **2FA**:登录页有验证码框,本期是钩子、不强制(SSO 企微/钉钉为 V2)。
- **运营方破玻璃**:本期关闭(返回"二期能力");只读 / 客户授权协助态可用。
- **成员密码交付**:本期"一次性回显给管理员/成员",邀请链接(邮件首次设密)随邮件能力后续上。
- **逐模型不同折扣率**:只做「整体折扣」「按分组折扣」,不做"同客户每个模型不同折扣"(上游 new-api 无此能力)。
- **折扣对账自愈的"检测告警循环"**:平台写折扣已防抹掉他人/手工配置;"己方折扣被外部改了自动纠回/
  基础倍率变了重算"的监控循环为最后一个增强项,未上。
- **邮件 / 站外推送通知**:本期只站内通知列表。

## 7. 测试重点(建议覆盖维度)

- **功能正确性**:每个角色的增删改查、代发 key、调额、审批三档流转、余额加减。
- **权限(RBAC)**:越权应被拒——成员不能开通成员/调额、组织管理员不能入账(动钱红线)、
  团队负责人不能跨团队、跨组织访问应 404、未登录应 401。
- **红线**:明文 API key 只在创建/轮换回显一次,列表/详情只见脱敏串;客户对价格只读。
- **样式 / 好用 / 美观**:页面布局、交互顺手度、文案、空状态、错误提示是否清楚。
- **健壮性**:重复提交、非法输入、并发(如重复入账同一转账号应被幂等挡下)。
